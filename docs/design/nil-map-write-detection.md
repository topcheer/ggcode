# Nil Map Write Detection

## Problem

In Go, the zero value of a map is `nil`. A nil map is valid for read operations (returns the zero value) but **panics** on any write operation:

```go
var m map[string]int
m["key"] = 1  // PANIC: assignment to entry in nil map
```

This is one of the most common runtime panics in Go code generated by AI agents. LLMs frequently declare the map variable type but forget the `make()` initialization. The error only manifests at runtime -- the code compiles cleanly.

`go vet` does NOT detect nil map writes. staticcheck doesn't either. This check provides zero-dependency static detection at write time in <1ms.

## Implementation

**File**: `internal/agent/nil_map_write_check.go`
**Pipeline**: Check #34b in `write_integrity.go`

### Detection Logic

1. Parse the Go file into an AST
2. For each function, find `var m map[K]V` declarations without initializers
3. Track whether the map is subsequently initialized via:
   - `m = make(map[K]V)`
   - `m = map[K]V{...}` (map literal)
   - `m = someFunc()` (assignment from expression)
4. If a write (`m[key] = value`, `m[key]++`) occurs before initialization, flag it

### False Positive Mitigation

- Only flags maps declared as local variables (not parameters or struct fields)
- Maps initialized via `make()`, literal, or any assignment expression are NOT flagged
- Delta-aware: only flags patterns newly introduced by the current edit
- Skips non-Go files and syntactically invalid code
- Deduplicates by variable name (reports first occurrence only)

### Test Coverage

12 tests covering:
- Basic panic case (var + write)
- Initialized with make (no warning)
- Initialized with literal (no warning)
- Short var decl with make/literal (no warning)
- Non-Go files (no warning)
- Delta-aware (unchanged code suppressed)
- Delta-aware (new instance detected)
- Read-only access (no warning)
- IncDec write (`m[key]++`)
- Assignment from function call (no warning)
- Syntax error handling (graceful skip)
