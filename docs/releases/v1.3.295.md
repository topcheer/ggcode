# ggcode v1.3.295

## Highlights

- **`/et` tunnels work again: the embedded etunnel SDK is v1.7.50 (#5978).** The etunnel server (v1.7.40+) gates clients at `hello` - an SDK that reports no `hello.version`, or is more than 5 patch releases behind, is refused with `client_outdated`. Our embedded v1.7.26 predates `hello.version`, so every `/et on`, `ggcode daemon --etunnel` and desktop tunnel handshake failed with "etunnel client did not report a valid version; this server runs 1.7.50 and requires SDK >= 1.7.45" (reproduced live against `wss://t.etun.uk/tunnel`; v1.7.50 connects). The SDK API is additive, no call site changed. When a future server does refuse this build, the handshake error now keeps the server's text verbatim and appends the ggcode-specific remedy ("this build embeds etunnel SDK X ... upgrade ggcode") - the upgrade URL in the server message points at the SDK repo, which is not what a ggcode user can act on (`internal/webui/tunnel_ctl.go`, `describeTunnelError`). Docs: `docs/guide/webui.md`.
- **Harness state never reaches a "what did I change" review surface (#5977).** `.ggcode/` (auto memory, checkpoints, usage / guidance statistics, compaction facts, skills, worktrees) is maintained by the harness as a side effect of running and is often tracked in the user's repository, so it shows up as `M` / `D` on every turn. Field incident (2026-11-26): in a repo with 484 tracked `.ggcode/` files the memory curator's churn made 452 of 475 porcelain lines harness state - the **Modified files** prompt section showed 20 lines of `.ggcode/` and folded the 23 real changes behind "... (453 more)", and the self-review made the agent spend a turn attributing "92 deletions" that were the curator's prune. Every surface that reviews "the agent's changes" now shares one rule (`util.IsHarnessStatePath` + the repo-root-anchored `:(exclude,top).ggcode` pathspec): the Modified files section (no section when only harness state changed), the self-review summary, the adversarial evaluator's diff (143 files / 5.9k lines -> 21 files / 76 lines on that repo) and `review_changes` (332 -> 2 untracked lines). Explicitly user-invoked `git_status` / `git_diff` are untouched. Also fixed there: `strings.TrimSpace` on the first porcelain line ate its leading status column (`" M path"` was parsed as path `"ath"`). Docs: `docs/design/context-management.md` ("Harness state never reaches a review surface"), `docs/design/guidance-injection-trim.md`.
- **A new session never inherits other workspaces' teams (#5976).** A fresh session has no confirmed id until its first message, so its swarm namespace was `""` and the teams directory collapsed onto the shared root `~/.ggcode/swarm/teams/`; `AutoRestoreSessionTeams` (run at startup) then restored every legacy `teams/<teamID>/` board other workspaces' older binaries had left there - a new instance started in a parent directory came up with five foreign teams (17 teammates) and re-persisted them under its own id on every later start. Without a namespace nothing is restored, every restore entry point returns `errNoConfirmedSession`, and `DeleteTeam` skips the on-disk removal. Docs: `docs/guide/persistent-teams.md` (legacy boards are archived, not adopted).
- **The error budget is a statistic, not a steering wheel (#5975).** The SLO error budget (20-call sliding window, 85% success) injected "[error-budget] fast burn ..." past 30% failures and "[error-budget] BUDGET EXHAUSTED ... Stop retrying ... ask the user" past 15% with >= 6 failures - not a hard stop, but text telling the model to stop and escalate, the same counter-driven family as the turn / budget / no-progress limits removed in v1.3.294. The window and `burnRate()` stay as read-only statistics (snapshot / introspection); nothing reaches the model. Two dead bodies with zero callers went with it (`confidenceState.maybeIntervene`, `consensusState.check`). The multi-dimensional `[trajectory-health]` composite warning is untouched on purpose. Docs: `docs/guide/error-budget.md`, `docs/design/agent-loop.md`, `docs/guide/uncertainty-calibration.md`.
- **iOS builds with Xcode 27 (#5971).** Apple flagged the 1.3.294 iOS build: "built with the iOS 26.2 SDK. Starting April 2027, iOS and iPadOS apps must be built with the iOS 27 SDK or later" (ITMS-90725). The cause was our own pin (`macos-15` + Xcode 26); the iOS job now runs on GitHub's `xcode-27` image with the newest stable 27.x. This release carries `1.3.295+2026112701`.
- **Site: SEO/GEO baseline, `llms-full.txt` and a correct `robots.txt` (#5972, #5973, #5974).** The home page emits an Organization + WebSite + SoftwareApplication `@graph` per locale (previously one English SoftwareApplication on every page, legal pages included); `llms.txt` and `llms-full.txt` are served (the Railway image had 404'd on `llms-full.txt` because the README was not in the build context); `robots.txt` actually ships and keeps the training reservation as a `Content-Signal` declaration instead of `Disallow` blocks that hid the site from Baidu / Claude / OpenAI crawlers; Caddy 301s the duplicate `/index.html`, `/zh` and `/sitemap.xml` URLs; a branded 404 page replaces an empty body; `apple-touch-icon.png` exists (it was 404) and 4xx responses are no longer cached for a year as immutable assets. `site-release.yml` purges the Cloudflare cache after each site deploy; Lighthouse CI asserts on the median of 3 runs. Details in `docs/site/SEO.md`.

## Upgrade notes

- **Upgrade to keep `/et` working.** Builds before this one embed etunnel v1.7.26, which the tunnel server no longer accepts (`client_outdated`); `/et on`, `ggcode daemon --etunnel` and the desktop Etunnel mapping fail until the binary is upgraded. No config changes.
- **Behaviour change: no error-budget steering.** A run with failing tool calls no longer receives "[error-budget] fast burn" / "BUDGET EXHAUSTED ... ask the user" messages; the AI decides when to stop retrying (same contract as v1.3.294's unbounded-by-default). The statistic is still visible in the snapshot / introspection.
- **Swarm:** a session without a confirmed id restores no teams; legacy `~/.ggcode/swarm/teams/<teamID>/` boards from older binaries are not adopted by current builds (archive command in `docs/guide/persistent-teams.md`).
- **Review surfaces** no longer list `.ggcode/` changes as yours; run `git_status` / `git_diff` explicitly if you want to see them.
