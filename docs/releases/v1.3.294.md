# ggcode v1.3.294

## Highlights

- **The agent loop no longer winds itself down or stops on counters nobody asked for (#5965, #5966, #5968).** Runs were being cut short by injected budget nudges and by default caps that were never configured. All of them are gone: there is no derived tool-call budget any more (it used to default to 500 calls, or `max_iterations*8`), no `[tool budget] ...` messages pushed into the context at 80% / 95%, no 60-call default cap on `spawn_agent` sub-agents, and the ACP loop no longer forces `max_iterations=100` when it is set to 0 (0 means unlimited everywhere, same as the main loop). Session budgets (`session_token_budget`, `session_cost_limit_usd`, `session_time_budget`) and the wall-clock `session_timeout` no longer inject "finalize current work ... prepare to conclude" / "wrap up secondary work" steering at 80% / 95%, and the `[token-waste] N% of your tool-result context budget` nudge is removed. In autopilot, the deterministic "3 consecutive no-progress rounds -> terminating to avoid deadlock" gate is removed too: the run now ends only when the strategist declares the goal achieved, the model ends its turn on its own, or you cancel - **the AI decides when to stop.** Explicitly configured caps (`max_iterations`, `tool_call_budget`, `max_tool_calls`, the session budgets) keep working as hard stops and announce the stop to you as a system event; nothing steering reaches the model any more. Docs: `docs/design/agent-loop.md`, `docs/guide/configuration.md`, `docs/guide/multi-agent-modes.md`, `docs/guide/modes.md`, `ggcode.example.yaml`.
- **Release assets are mirrored at download.ggcode.dev.** A Cloudflare Worker (`workers/download-mirror`) mirrors the GitHub release assets with zero per-release work: it resolves `releases/latest`, builds `manifest.json` from the tag's `checksums.txt`, streams the assets from GitHub and caches them at the edge (immutable per tag, HTTP Range pass-through). `install.sh` / `install.ps1` now default `GGCODE_DOWNLOAD_BASE` to the mirror and fall back to GitHub at every step; the asset copy step in the release workflow is retired, and the retired `https://ggcode.dev/downloads/latest/*` path (which the v1.3.293 installers still point at) is forwarded to the mirror so old scripts keep working. A CodeQL polynomial-ReDoS alert in the Worker's trailing-slash trim was fixed by dropping the regex.
- **One-line installers are actually published (#2cd66cbcf).** `https://ggcode.dev/install.sh` and `https://ggcode.dev/install.ps1` are served from the site: OS/arch detection, latest-tag resolution via the mirror manifest with GitHub fallbacks, SHA-256 verification against `checksums.txt`, a no-sudo install into `~/.local/bin` / `%LOCALAPPDATA%\ggcode\bin` (user PATH), a printed version, and a dry run on both. The site dropped the npm install tab, fixed the Homebrew tap and the App Store / Google Play links, and `install.ps1` no longer crashes on Windows PowerShell 5.1 when the mirror manifest is missing and it falls back to the GitHub `releases/latest` redirect (a user-reported `irm https://ggcode.dev/install.ps1 | iex` failure).
- **Mobile ships on every tag (#2d4b4aded).** The Android and iOS build jobs were gated on a `mobile/**` diff against the previous tag, so tags without mobile changes (v1.3.293 included) finished in seconds with no mobile build. Every `v*` tag now builds and ships the app; the mobile version and build number are bumped in every release commit (`docs/release-process.md` §3.5 / §9). This release carries `1.3.294+2026112601`.

## Fixes and improvements

- agent: `TestNoBudgetLongRunNeverStops` (110 turns / 550 calls, `max_iterations` 0, no budget -> clean completion), `TestSessionBudgetCrossingsNeverInjectedIntoContext` (an explicit 10-token budget hard-stops at 100% with the user-facing event, no `[token budget]` text in the context), `TestTokenWasteGuidanceGone`, `TestAutopilotNoProgressNeverForceTerminates` (six consecutive text-only rounds: the strategist is consulted seven times and ends the run by declaring the goal achieved) pin the new contract
- agent: the no-progress streak is still tracked, only as the `no_progress_streak` status statistic; the per-run strategist call budget (100) is unchanged - it bounds the oversight process, not the agent
- tests: two pre-existing `verify-ci` flakes fixed - `lanchat` `TestIssue989CustomKeyDMEndToEnd` raced the receiver's detached key-pin write against `t.TempDir()` cleanup (#6375937a6); `a2a` ephemeral test servers bound `0.0.0.0:0`, and on macOS a wildcard bind is allowed even when `127.0.0.1:<same port>` is already taken by another listener, so the tests now bind `127.0.0.1` explicitly (#0f341bcad)
- release prep: `make sync-model-caps` was run and its diff was **rejected**, as for v1.3.293 - upstream models.dev still lists `glm-5.4` with a 1,000,000 context window (the built-in row from #5926 pins 1,048,576) and still drops the W47 calibration row `claude-opus-4.7`, so the regen fails `TestInferContextWindow_KnownModels` and `TestWeeklyCalibrationW47`. The capability table therefore ships unchanged; re-run the sync once the upstream rows agree with the pinned values
- docs: `docs/guide/install.md` / `install-linux.md` / READMEs synced with the one-line installers (lowercase asset names, no sudo, the unpublished winget command and the stale npm/pip links dropped)

## Upgrade notes

- **Behaviour change: unbounded by default.** A run with no explicit caps no longer stops on a default turn / tool-call limit and no longer receives "wrap up" steering. If you want a bound, set it explicitly - `max_iterations`, `tool_call_budget`, `max_tool_calls`, or a `session_*_budget` / `session_timeout`; each still hard-stops and tells you. Autopilot runs no longer self-terminate on "no progress": cancel the run if you want it to stop before the strategist declares the goal achieved.
- **Install:** `curl -fsSL https://ggcode.dev/install.sh | sh` (or `irm https://ggcode.dev/install.ps1 | iex` on Windows). Downloads default to `https://download.ggcode.dev/latest`; set `GGCODE_DOWNLOAD_BASE` to go straight to GitHub.
- **No config changes.** The removed defaults need no migration; an explicit `tool_call_budget` or `max_iterations` keeps working exactly as before.
