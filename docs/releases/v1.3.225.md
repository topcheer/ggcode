# Release v1.3.225

## Panic Safety (crash containment series)

This release closes out the v1.3.224 crash audit: every goroutine launch,
including the main goroutines, is now panic-contained.

### Goroutine Sweep + CI Gate
- **55eb91c1**: recover-guarded all unprotected goroutine launches behind
  `safego` (P0/P1 sites from the crash audit)
- **587795b4**: new AST-based CI gate (`scripts/dev/goroutine_check.go`)
  rejects any `go` launch that is not safego-protected (or explicitly
  allowlisted with a justification) — the invariant can no longer regress.
  Swept 5 stragglers in the same pass (cron patrol, section collector,
  fallback drain, report scan workers)
- **587795b4**: `webui` auth token generation no longer panics when
  `crypto/rand` fails (was a process-killer at CLI/daemon startup); falls
  back to a logged weak token instead

### Main-Goroutine Containment
- **2383f655**: panic in `RunStreamWithContent` is now converted to a
  returned error — the session survives a panicking run instead of dying
  with the process. Existing defers (journal, stats, persistence) run
  normally during unwinding (defer LIFO verified)
- **2383f655**: crash journal at `~/.ggcode/crash/` — CLI and desktop
  entry points now write panic + stack to disk before exiting, with a
  readable stderr note pointing at the log
- **7051d2f9**: independent review fixes — desktop crash notes no longer
  lost to the stderr pipe (MAJOR), debug ring flushed before exit,
  Stringer-panic guard in the crash logger, component path sanitization,
  1 MiB stack cap, pre-panic error preservation
- **3b99cdfc**: contract test pinning panic-to-error conversion
