# ggcode v1.3.293

## Highlights

- **WebUI tool cards read like the tool, not like JSON.** Every tool call is rendered with the same display layer the TUI, IM, desktop and mobile tunnel use (`tool.DescribeTool` / `tool.DescribeToolResult`): a header that gives the conclusion first - status, kind icon, friendly name (`Read internal/webui/server.go`, `Run echo hi`, `Server › Tool` for MCP), a result badge (line count, match count, exit failure reason) and duration - and a body shaped per kind: a shell block plus stdout / `STDERR:` / `Command failed:` sections for commands, a line-numbered code view for reads, an inline `old_text → new_text` diff for edits (coloured, with `−n +m` counts), content preview for writes, matches grouped by file for grep, markdown for web pages, a checklist for `todo_write`. Large output is truncated with "show all"; every card can flip to the raw JSON. Results attach to the exact call by id, so parallel same-name calls no longer cross. This also fixes a long-standing gap: after a reload the webui never showed tool results at all (the history loader looked for them in the wrong message); they are now attached across messages by `tool_id`, and the model-facing `<untrusted_tool_output>` fence is stripped from what humans see.
- **Approvals and `ask_user` questionnaires reach browser tabs (#5865).** A webui session drives the same agent as the TUI, but a pending approval or question used to go unanswered until it timed out. The ws protocol now carries `interaction` / `interaction_resolved` events: pending requests are replayed on (re)connect, the page shows an `InteractionBanner` (allow / always allow / deny; single, multi or freeform questions), and the answer routes back to the TUI or daemon host. The first answer wins across TUI key, IM, tunnel and webui, and every other surface clears.
- **WebUI sidebar: icons, honest footer, immersive mode.** Nav items use a shared linear SVG icon set (the chat item finally has one); the footer no longer says `P1 · 聊天 · 建设中` but shows the connection state and current workspace; on desktop the left sidebar collapses with `⌘/Ctrl+B`, a header toggle or the command palette so the conversation spans the full width (preference persisted). The right activity pane only takes its column when it has content, and the welcome-screen quick entries dropped their milestone jargon.
- **Headless Chrome no longer burns CPU after a `browser` call.** Idle profiles are reaped after 3 min (`GGCODE_BROWSER_IDLE_SECS`), headless tabs are frozen after every action (measured 441% → 0.0% GPU), a dead browser self-heals on the next call instead of bricking the tool, and the macOS "keychain cannot be found" modal that blocked startup from agent sessions is gone (`--use-mock-keychain`).
- **TUI status bar: 150 ms per spinner tick → linear.** Long status texts (a queued image paste during a long `run_command`) made every render spend ~145 ms truncating the bar - the UI goroutine was ~97% busy. Both truncation loops now use the linear `fitDisplayWidth`, and slow bars name the culprit part in the debug ring.
- **Swarm: the leader can watch teammates live.** `subagent_context` now covers `tm-*` teammates (200-event ring, same format as sub-agents); reasoning deltas are coalesced per segment instead of flooding the ring per token, long phases are time-boxed into events every 2 s so "thinking" and "stuck" are distinguishable, and tool results are attributed by call ID under parallel calls.

## Fixes and improvements

- webui: `tool_result` events and history blocks carry `id` / `summary` / `payload` / `payload_mode`; thinking is carried into history as reasoning; empty result-only user messages are not rendered as bubbles
- webui: right-pane pin toggle exposed in the command palette (it was unreachable on desktop)
- webui: the queued-messages banner no longer outlives the turn - the `append` event carried the TUI bubble text (image placeholder prefix) while `dequeue` carried the raw text, so a message with an image never matched and the banner stayed forever; all three (append / dequeue / snapshot) now carry the canonical text, every queue event ships the full snapshot with a monotonic `seq` (snapshot wins, stale seq dropped, lost events self-heal), and the banner is a centered column-width strip instead of spanning the window
- webui: the reasoning block is an aside now - no purple box, a thin left rule with neutral muted text (the old `#7c3aed` text on a purple tint was barely legible in the dark theme), collapsed to one line with a line count once the turn finishes
- webui dist is built with the pinned pnpm toolchain so the `webui-dist-freshness` check matches CI
- docs: `docs/guide/webui.md` documents the tool cards, the approval banner and the collapsible sidebar; `docs/guide/multi-agent-modes.md` notes live context for both `agent-*` and `tm-*`; README notes the automatic idle shutdown of browser instances
- release prep: `make sync-model-caps` was run and its diff was **rejected** - upstream models.dev now lists `glm-5.4` but with a 1,000,000 context window (the built-in row from #5926 pins 1,048,576) and drops the W47 calibration row `claude-opus-4-7`, so the regen fails `TestInferContextWindow_KnownModels` and `TestWeeklyCalibrationW47`. The capability table therefore still ships as of W48; re-run the sync once the upstream rows agree with the pinned values.
- mobile: no `mobile/` changes in this range, so the mobile build number was not bumped (same as v1.3.285-v1.3.292)

## Upgrade notes

- **No config changes.**
- **WebUI**: `⌘/Ctrl+B` toggles the left sidebar on desktop; the collapse state is remembered per browser.
- **Browser tool**: an idle headless Chrome is closed after 3 minutes; set `GGCODE_BROWSER_IDLE_SECS=0` to disable the reaper.
