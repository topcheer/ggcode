# v1.3.266

发布日期：2026-10-22

自 v1.3.265 以来 66 个提交（含 PR #4283–#4342）。聚焦：**refusal ledger 提取与执行强化**（leave-alone 分支复活）、**memory 时间点读取消歧**（ReadMemoryAsOf 墓碑修复）、**权限/命令门修复**、mattermost 提及边界修复，以及多波次 deadcode/i18n 清理。

## Refusal Ledger 强化

- **leave-alone 提取分支复活（PR #4342，#4340）**：旧正则 `leave\b[^n]{0,5}alone` 的间隙双排除（`[^n]` + 5 字符上限）使 "leave config.yaml alone" 类真实宾语全部静默漏提取，30 天跨 run 硬块对该句式完全不生效。修复放宽为行内有界 `[^\n]{0,40}`，真实文件名/代词宾语恢复入库；伴测锚定 them/that/config.yaml/main.go/nginx.conf 全形态
- 源判别加固（#4284 系）：引文/日志/提示词碎片不再被强制执行
- token 起始边界修复：refusal 标志/路径锚点不再命中前缀重叠词
- 读豁免管道/复合写向量覆盖（#4338 修复在 PR 队列中，见下版）

## Memory 修复

- **ReadMemoryAsOf 双删墓碑（PR #4335，#4334）**：历史版本区间读取时，同一 key 的两次独立删除只保留最后一个墓碑，导致早期区间错误命中已删除条目。改为 per-deletion 墓碑，两个删除间隙均可正确读取

## 权限与命令门

- **isCommandTool 覆盖 Windows shell 名（PR #4302，#4290）**：powershell/cmd/pwsh 大小写不敏感匹配，Windows 侧命令工具识别不再漏
- 命令门 ask 语义修复（#4273 后续）：shell 语法原语触发 ask 而非危险语义判定（#4291）
- 审批账本区分降级 allow 与 denial（#4273/#4274）

## 其他修复

- **mattermost 提及边界（PR #4324，#4322）**：用户名以 `-`/`.` 结尾时提及解析不再吞并边界字符
- TUI：memory consolidation 结果不再渲染为启动通知（#4319 系）
- 流中断真实性 + verify 债务排除（#4232/#4234/#4239）
- xargs 写证据前缀组补 sudo 包裹形态（#4344 修复排队中）

## 清理

- deadcode 清理波次（#4328/#4330/#4332/#4336 等）：确认死代码移除、i18n 死键多轮清理（desktop 前端 175 键、TUI 模块目录 80 键、Flutter 资产 23 键等）
- flake 根治（#4293）：测试稳定性修复

## 升级注意

- 用户此前使用 "leave X alone" 措辞的持久拒绝条目，升级后将真正被提取并强制执行（此前静默失效）；如出现误块可用 `/refusals clear` 清理
