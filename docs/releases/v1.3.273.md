# ggcode v1.3.273

## Highlights

- **Windows TUI restored**: the CLI no longer forces every Windows user into the linear plain frontend — Windows terminals (cmd/PowerShell/Windows Terminal) do not set `TERM`, which the dumb-terminal detection misread; only an explicit `TERM=dumb` opts Windows out of the TUI now (#5009).
- Sub-agent reliability: a generic GLM 400 ("messages 参数非法") is now recognized as context overflow so reactive compaction recovers instead of the run dying mid-task (#5001).
- Agent context window derives from provider model metadata (128k fallback) and sub-agents can compact early at 70% of that window (#5003, #5008).
- New tool: `session_recall` — keyword-search full session transcript history (including tool results) via a trigram inverted index, so details compacted out of context stay recoverable (#4999).

## Fixes and improvements

- cli: Windows empty-TERM no longer selects plain frontend; Unix behavior unchanged (#5009)
- provider: GLM parameter-illegal 400 phrasings recognized as context overflow with pin tests (#5001)
- agent: context window from provider metadata with 128k fallback (#5003); sub-agent early-compact ratio opt-in (#5008)
- tool: `multi_file_read` no longer silently drops a second window of the same file (#4993); dead wrapper `formatMultiFileReadFileBlockWindow` removed (#5000, #5004)
- tool: raw `worktree add` without `-b` fails fast at creation instead of surfacing at push time; detached-HEAD detection hardened (#4996); dead helpers removed (#5000)
- agent: `cvExtractPathAfter` directory-suffix fallback restored — suffix matching no longer dead-code-skipped, ending systematic scope-constraint under-reporting (#5007); wider trim set + end-to-end chain coverage absorbed from #5008
- sessionidx: session-recall index package with per-instance ownership and size gates (#4999)

## Upgrade notes

- Windows users: to keep the linear plain frontend, pass `--plain` explicitly or set `TERM=dumb`.
- `session_recall` builds per-session indexes under `~/.ggcode/sessions/idx/` on first use; sibling-session indexes refresh every 30 minutes.
