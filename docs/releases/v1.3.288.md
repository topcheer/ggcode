# ggcode v1.3.288

## Highlights

- **Swarm: direct-delivered tasks now land on the board when finished (f614a7fbd).** `swarm_task_create` with an assignee delivers the task to the teammate's inbox, but the direct path never wrote the board on completion - finished tasks stayed `pending` forever, and every restart's idle poller re-claimed and re-ran work the user had already received ("teammate shows working right after restore, redoing finished work"). The runner now marks the task `completed` (guarded update) as soon as execution succeeds; failure paths keep existing retry semantics.
- **Swarm: restart-storm redo loop parked (1aa2894c1).** A ctx-cancel rollback could requeue the same task indefinitely across repeated restarts; the rollback now parks the task at a retry ceiling instead of looping forever.
- **Permission: runaway command-pattern compilation refused (fe693cc7c).** A pathological deny-rule pattern could stall startup and balloon RSS (fleet 2.5GB startup incident); such patterns are now rejected before compilation and compiled regexes are cached process-wide.
- **TUI/chat render-path performance (8be998aa6, 1c344039d).** Render-path regexes hoisted out of per-frame tool renders, and the composer cost hint no longer copies the full UsageHistory every frame.

## Fixes and improvements

- fix(swarm,tool): teammate_results returns the archived per-task result instead of the session-level last output - fixes result misattribution and duplicate completion reports (62fc90c91)
- fix(tool,agentruntime): team tools reject unconfirmed sessions instead of panicking (#5867, 4121febf7)
- perf(tui,session): composer cost hint stops per-frame full UsageHistory copies (#5868)
- perf(chat): render-path regex hoist with A/B benchmarks (#5831/#5867 evidence)
- docs(design): per-frame allocation rule for render paths; swarm forensics notes pinned
- Release-process note: an experimental "freeze pre-restart tasks on restore" change (07614d0b0) was reverted (ec7336829) after live fleet feedback - restored teams keep the resume-on-restart behavior; completion now lands on the board instead.

## Upgrade notes

- No config changes. Teams restored from previous versions will keep resuming interrupted work on restart, as before; the difference is that completed direct-delivered tasks no longer get re-run.
- Operators who hand-edited board JSON files under `~/.ggcode/swarm/teams/` should let the runner own board state going forward; the completion path is now closed-loop.
