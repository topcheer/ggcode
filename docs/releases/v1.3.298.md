# ggcode v1.3.298

## Highlights

- **`mobile_device` drives iOS simulators through idb first - and installs it for you.** On macOS the tool now goes through idb (companion + client) instead of AppleScript `System Events` clicks: logical-point taps, text input and the accessibility tree all work without a visible Simulator window and without Accessibility permission. `snapshot` returns `@eN` element refs with `rect`s in logical points (explicit `x`/`y` stay screenshot pixels and are divided by the device scale), `tap ref=@e5` taps the element centre, and the tool description says so. When idb is missing, a detached one-shot installer trusts only the idb maintainers' Homebrew tap (`meta/fb` / `facebook/fb` - Homebrew 7 refuses formulae from untrusted taps), installs `idb-companion` and puts the `fb-idb` client into a ggcode-owned virtualenv (`~/.ggcode/idb`): no pipx, no PEP 668, no `PATH` changes, and it never blocks the tool call (the action falls back to AppleScript and reports that the installation is in progress; log in `~/.ggcode/logs/idb-install.log`; `GGCODE_MOBILE_NO_INSTALL=1` disables it). Verified by uninstalling idb and letting the tool reinstall it from scratch. Only connection-class errors reconnect and retry - a retried `ui text` used to type everything twice. New guide: `docs/guide/mobile-device-tool.md`.
- **`type` into iOS fields works with Chinese and Japanese keyboards.** `idb ui text` sends HID keystrokes that pass through the simulator's input method: a `wss://` connect URL came out as `wss：//gateway。ggcode。dev…` under the Pinyin IME. The tool now writes the text to the pasteboard (reading it back until the device sees it), waits until a text field reports keyboard focus (otherwise it refuses with "tap the field first"), long-presses an empty field and taps the edit menu's **Paste** item (a real user gesture, so iOS never raises the cross-app paste confirmation), or sends `⌘V` and confirms the callout on a non-empty field; the result says which path was used. Verified byte-exact for a 357-character URL, pure Chinese + emoji and mixed strings, in the real app, through the real tool path.
- **Mobile: the connecting screen is no longer a dead end, the workspace sheet's handle really dismisses, and you can send while the agent runs.** The full-screen progress view had no control at all - a hung handshake or a host that never sent session data trapped the user on it. It now has **Cancel**; a relay sync that makes no progress is flagged as stalled after 30 s and abandoned after another 30 s with an error back on **Connect**; the handshake is bounded by a timeout. Cancelling and then retrying used to be silently swallowed (the retry was coalesced into the cancelled, still-pending handshake) - fixed. `showModalBottomSheet(showDragHandle: true)` painted a bar with no tap and no semantics while the accessibility tree advertised the barrier's "Dismiss" over it; the workspace sheet now uses a `SheetDismissHandle` (44 pt hit area, button semantics, same label). While the agent is running the composer promised "you can still send a message" but offered only Stop - **Send** now appears next to Stop once there is a draft.
- **`/share stop` no longer poisons the next `start_share`.** The TUI's close path cleared the model side and detached the online broker but never released `TunnelHost.activeShare`, so every later `start_share` in the same session was refused with "already active". The new `TunnelHost.ReleaseShare()` is called on the close path (and by `stop_share` as a fallback). Mobile **Clear all cached data** now also drops the persisted selection, so the next launch starts on **Connect** instead of a "cached historical session" dead end.

## Fixes and improvements

- mobile_device (iOS): idb-first control with element refs, asynchronous auto-install, paste-based text input, keyboard-focus check, connection-only retry; snapshots report `Driver: idb`; `list_apps`, `launch`, `snapshot`, `tap`, `type`, `swipe` and `screenshot` were exercised through the real tool path on a dedicated simulator
- mobile: Cancel on the progress view, two-stage relay-sync watchdog, handshake backstop, `_connectInFlight` cleared on cancel/abandon, `SheetDismissHandle`, Send next to Stop while busy; new keys `connect.timeout` / `connect.sync_timeout` in 10 locales
- tunnel: `ReleaseShare()` fixes the share-state leak after `/share stop`
- docs: `docs/guide/mobile-device-tool.md` (new), `docs/guide/mobile.md`, and the review report §8-§9 with the live-verification evidence and the open findings
- tests: Flutter analyze clean and `flutter test` 154/154 (idb locator / paste / focus / retry unit tests against a fake runner, provider tests for the handshake timeout, the stall watchdog and retry-after-cancel, widget tests for Cancel, the dismiss handle and Send-while-busy); Go `tool` / `agentruntime` / `tui` packages with `-race`
- release prep: `make sync-model-caps` was run and its diff was **rejected**, as for v1.3.293-v1.3.297 - upstream still lists `glm-5.4` with a 1,000,000 context window (the built-in row pins 1,048,576) and still drops the W47 calibration row `claude-opus-4.7`; the capability table ships unchanged

## Upgrade notes

- **`mobile_device` on macOS may install idb in the background** the first time it runs (Homebrew `idb-companion` + `fb-idb` into `~/.ggcode/idb`). Set `GGCODE_MOBILE_NO_INSTALL=1` to keep the AppleScript-only behaviour.
- **The mobile progress view has a Cancel button**, and a relay sync that makes no progress for 60 s returns to **Connect** with an error; reconnect explicitly if the host was only slow.
- **The mobile composer shows Send next to Stop while the agent runs** once you have typed a draft.
- **No config changes**; the capability table ships unchanged.

## Known issues

- A message sent from the mobile composer while the agent is running is shown twice in the mobile chat (the local bubble and the host echo are not merged on that path); idle-time sends were not reproduced. Tracked in `docs/reviews/desktop-mobile-ux-motion-review-2026-11-27.md` §9.
- On a Mac where other automation shuts simulators down or deletes them, idb fails with `dtuhidd ... invalidated`; use a dedicated simulator.
